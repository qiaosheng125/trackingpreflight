# 扫描成本控制清单

更新时间：2026-06-02

Tracking Install Checker 一旦接入真实浏览器扫描，主要风险不是页面渲染，而是扫描接口被刷导致 Browserless、worker、带宽或队列成本失控。

## 当前原型已有

- URL 安全校验雏形。
- 每客户端 key 每分钟 12 次内存限流。
- 扫描中按钮禁用，减少重复提交。
- mock API，不产生真实浏览器成本。
- `npm run test:api` 行为测试，覆盖 URL guard 和请求体校验。

## 正式接 Browserless 前必须完成

- [ ] 每 IP 每分钟限制。
- [ ] 每 IP 每天限制。
- [ ] 全站每分钟扫描上限。
- [ ] 单次扫描超时。
- [ ] 浏览器并发上限。
- [ ] 相同 URL 短时间缓存。
- [ ] 禁止扫描 localhost / 内网 / 非标准端口。
- [ ] DNS 解析后校验 IP。
- [ ] 跳转后的 final URL 重新校验。
- [ ] 失败请求不无限重试。
- [ ] 返回 429 时给用户明确提示。
- [ ] 记录扫描量、失败量、平均耗时。

## 建议初始限制

未登录用户：

- 每 IP 每分钟：3 次
- 每 IP 每天：20 次
- 单次扫描超时：20 秒
- 同 URL 缓存：10 分钟

登录用户：

- 每用户每分钟：6 次
- 每用户每天：100 次
- 单次扫描超时：30 秒
- 同 URL 缓存：5 分钟

全站：

- 同时运行浏览器：1-3 个
- 队列最大长度：50
- 超过队列直接返回 429

## 预警指标

出现以下情况视为异常：

- 每分钟扫描数突然超过平时 5 倍。
- 同一 IP 连续扫不同 URL。
- 同一 URL 被重复扫超过 20 次/小时。
- 平均扫描耗时超过 20 秒。
- 失败率超过 50%。
- Browserless 配额一天内消耗超过预计 30%。

## 产品层防刷

- 首页不要自动扫描。
- 用户必须点击按钮才扫描。
- 扫描中按钮禁用。
- 对重复 URL 显示缓存结果。
- 免费版报告可以延迟返回。
- 高级事件扫描只给登录用户或付费用户。

## 当前结论

第七站未正式上线前，不能接公开无限制真实扫描 API。
